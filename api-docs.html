Kafka Olay Sözleşmeleri

KRaft modu · Zookeeper gerektirmez · Yedek: Redis Streams (EventBus arayüzü)
disaster.declared
Yayıncı:disaster-service
Dinleyen:disaster-service, agent-service
Yeni afet ilan edildi. agent-service dinleyerek ajan döngüsünü başlatır.
{ "event_id": "evt_001", "tur": "deprem", "buyukluk": 7.4, "iller": ["Hatay", "Kahramanmaraş"], "zaman": "2026-10-16T04:17:00Z" }
customer.affected
Yayıncı:disaster-service
Dinleyen:agent-service
Bir müşteri afetten etkilenmiş sayıldı. Her müşteri için ayrı olay yayınlanır.
{ "event_id": "evt_001", "customer_id": "cust_072", "il": "Hatay", "eslesme_zamani": "2026-10-16T04:18:02Z" }
plan.drafted
Yayıncı:agent-service
Dinleyen:agent-service (SSE)
Müşteri için plan taslağı ve bildirim hazır. SSE üzerinden ön yüze iletilir.
{ "plan_id": "plan_001", "customer_id": "cust_072", "oncelik": "yuksek", "erteleme_ay": 4, "durum": "taslak" }
plan.approved
Yayıncı:agent-service
Dinleyen:core-service
Müşteri onayladı. Banka çalışanının incelemesine gider. Hiçbir şey otomatik onaylanmaz.
plan.escalated
Yayıncı:agent-service
Dinleyen:çalışan konsolu
Temsilciye devredildi. Ajan hata verdiyse veya müşteri "Temsilci beni arasın" diyip süresi dolduysa tetiklenir.

auth-service:8001

Kayıt/giriş, JWT üretimi, RBAC (customer · staff · admin)
POST/auth/register Yeni kullanıcı kaydı Public▶
Request Body
AlanTürDurumAçıklama
emailstringZorunluGeçerli e-posta adresi
passwordstringZorunluMin 8 karakter; bcrypt ile saklanır
roleenumOpsiyonelcustomer | staff | admin (varsayılan: customer)
customer_idstringOpsiyonelMüşteri rolü için core-service'deki müşteri ID'si
Örnek İstek
{ "email": "hatice@example.com", "password": "guvenli_sifre", "role": "customer", "customer_id": "cust_072" }
Örnek Yanıt (201)
{ "user_id": "usr_001", "email": "hatice@example.com", "role": "customer", "created_at": "2026-10-16T05:00:00Z" }
Yanıt Kodları
201Kullanıcı başarıyla oluşturuldu
409Bu e-posta adresi zaten kayıtlı
422Geçersiz e-posta veya eksik alan
POST/auth/login JWT token al Public▶
Örnek İstek
{ "email": "hatice@example.com", "password": "guvenli_sifre" }
Örnek Yanıt (200)
{ "access_token": "eyJhbGciOiJIUzI1NiJ9...", "token_type": "bearer", "expires_in": 3600, "role": "customer" }
Yanıt Kodları
200Token başarıyla verildi
401Hatalı e-posta veya şifre
GET/auth/me Oturum açık kullanıcı bilgisi JWT Gerekli▶
Header: Authorization: Bearer {token}
Örnek Yanıt (200)
{ "user_id": "usr_001", "email": "hatice@example.com", "role": "customer", "customer_id": "cust_072" }
200Kullanıcı bilgisi döner
401Geçersiz veya süresi dolmuş token

disaster-service:8003

Afet olayı alma, etkilenen müşteri eşleme, Kafka'ya yayın
POST/disaster/trigger Afet simülasyonu başlat admin▶
⚠️ Yalnızca admin rolü bu uç noktaya erişebilir. Demo/simülasyon içindir. Gerçek sistemde AFAD/Kandilli akışı otomatik tetikler.
Request Body
AlanTürDurumAçıklama
turstringZorunludeprem | sel | yangin
buyuklukfloatZorunluRichter ölçeği (örn: 7.4)
illerstring[]ZorunluEtkilenen iller listesi
zamandatetimeOpsiyonelISO 8601 (varsayılan: şu an)
kaynakstringOpsiyonelvarsayılan: "SIMULASYON"
Örnek İstek — Hatice Hanım Senaryosu
{ "tur": "deprem", "buyukluk": 7.4, "iller": ["Hatay", "Kahramanmaraş", "Malatya", "Adıyaman", "Gaziantep"], "zaman": "2026-10-16T04:17:00Z" }
Örnek Yanıt (201)
{ "event_id": "evt_001", "etkilenen_musteri_sayisi": 258, "yuksek_oncelikli": 76, "kafka_yayinlandi": true, "mesaj": "Afet bildirimi islendi, ajan sistemi baslatildi." }
201Afet oluşturuldu, Kafka'ya yayınlandı
403admin yetkisi gerekli
422Geçersiz alan veya eksik veri
GET/disaster/events Tüm afet olayları staff · admin▶
Örnek Yanıt (200)
{ "total": 1, "items": [{ "id": "evt_001", "tur": "deprem", "buyukluk": 7.4, "iller": ["Hatay", "Kahramanmaraş"], "etkilenen_sayisi": 258 }] }
GET/disaster/{event_id}/affected Etkilenen müşteriler (öncelik sırasında) staff · admin▶
Örnek Yanıt (200)
{ "event_id": "evt_001", "total": 258, "items": [{ "customer_id": "cust_072", "oncelik": "yuksek", "il": "Hatay", "yas": 72, "hassas": true }] }

agent-service:8004

Ajan A (Planlayıcı) + Ajan B (İletişimci) · planlar · onay akışı · SSE canlı bildirim
POST/agent/run Belirli müşteri için ajan döngüsünü başlat admin · staff▶
Normalde Kafka customer.affected olayı ile otomatik tetiklenir. Bu uç nokta test ve yeniden çalıştırma içindir.
Request Body
AlanTürDurumAçıklama
customer_idstringZorunluİşlenecek müşteri ID'si
event_idstringZorunluİlgili afet olay ID'si
Örnek İstek
{ "customer_id": "cust_072", "event_id": "evt_001" }
Örnek Yanıt (201) — Hatice Hanım Planı
{ "run_id": "run_001", "plan_id": "plan_001", "customer_id": "cust_072", "oncelik": "yuksek", "erteleme_ay": 4, "belgeler": ["kimlik", "hasar_tespit", "tapu", "dask_police_no"], "mesaj": "Sayın Hatice Hanım, geçmiş olsun...", "adim_sayisi": 6, "sure_ms": 3240, "durum": "taslak" }
GET/agent/plans Tüm planlar (filtreli, sayfalı) + ajan adım detayları JWT Gerekli▶
Query Parametreleri
ParametreTürAçıklama
event_idstringAfet olay ID'si filtresi
customer_idstringMüşteri ID'si filtresi (müşteri portalı için)
durumenumtaslak | onaylandi | devredildi | iptal
oncelikenumyuksek | normal
Örnek Yanıt (200)
{ "plan_id": "plan_001", "oncelik": "yuksek", "erteleme_ay": 4, "durum": "taslak", "adimlar": [{ "adim": 1, "arac": "musteri_bilgisi_getir", "sure_ms": 120 }, { "adim": 2, "arac": "oncelik_belirle", "cikti": "yuksek" }, { "adim": 3, "arac": "belge_listesi_getir" }, { "adim": 4, "arac": "erteleme_taslagi_olustur", "cikti": "4 ay" }] }
POST/agent/plans/{plan_id}/approve Müşteri planı onaylar customer▶
🔐 Hiçbir erteleme otomatik gerçekleşmez. Müşteri onayından sonra plan banka çalışanının kontrol kuyruğuna girer. Karar insandadır.
Örnek Yanıt (200)
{ "plan_id": "plan_001", "durum": "onaylandi", "onay_zamani": "2026-10-16T07:42:13Z", "mesaj": "Talebiniz degerlendirme icin banka calisanina iletildi." }
200Plan onaylandı, çalışan kuyruğuna gönderildi
403Yalnızca planın sahibi müşteri onaylayabilir
409Plan zaten onaylanmış veya devredilmiş
POST/agent/plans/{plan_id}/escalate Temsilciye devret (müşteri talebi veya ajan hatası) customer · ajan (oto)▶
Müşteri "Temsilci beni arasın" dediğinde veya ajan hata verdiğinde otomatik tetiklenir. Müşteri asla sahipsiz kalmaz.
Request Body (opsiyonel)
AlanTürAçıklama
nedenstringmusteri_talebi | ajan_hatasi | sure_asimi
Örnek Yanıt (200)
{ "plan_id": "plan_001", "durum": "devredildi", "neden": "musteri_talebi", "mesaj": "Temsilcimiz en kisa surede sizi arayacaktir." }
GET/agent/stream SSE — Canlı plan akışı (Redis üzerinden dağıtılır) JWT Gerekli▶
Server-Sent Events bağlantısı. Next.js ön yüzü bu akışı dinleyerek çalışan konsolunu ve müşteri bildirim ekranını gerçek zamanlı günceller.
Query Parametresi
ParametreTürAçıklama
event_idstringBelirli afet olayını filtrele (opsiyonel)
